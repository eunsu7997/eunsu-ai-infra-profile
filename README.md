# 나를 소개하는 한 페이지 — 유은수

AI 인프라 엔지니어를 준비하는 과정을 한 페이지에 담은 과제 결과물입니다.

## 실행
별도 설치가 필요 없습니다. `index.html`을 브라우저에서 열면 됩니다.

## 배포 추천
GitHub 저장소에 네 파일을 올린 뒤 GitHub Pages를 켜거나, 정적 사이트 배포 서비스에 배포하세요.
제출 시 **공개 결과물 URL**과 **전체 소스가 다시 열리는 HTTPS 저장소 URL(커밋 포함 권장)**을 입력합니다.

## 채점 항목 자체 점검
- 대상/목적 한 문장
- 공개 정보 3개 / 공개하지 않는 정보 3개
- 강점·특징 3개에 상황/행동/결과 근거
- 반응형: 1366×768, 1920×1080 및 작은 화면 대응
- 가로 넘침 방지
- 실제 링크/버튼 동작
- Tab 포커스 및 기본 button의 Enter/Space 키보드 작동
- 제목 계층 h1 → h2 → h3
- 본문 기본 16px 이상 및 충분한 대비
- 움직임 줄이기 버튼 + prefers-reduced-motion 지원
- 비밀번호/토큰/API 키 미포함

## 제출용 재현·통과 확인 4가지
어디로 가나요: 제출한 공개 결과물 URL
무엇을 하나요(3단계 이내): ① EVIDENCE로 이동 ② 강점 카드 클릭 ③ Tab 후 Enter/Space로 다른 카드 실행
무엇이 보이면 통과: 소개·공개범위·강점 3개와 상황/행동/결과가 보이고 카드가 마우스와 키보드로 펼쳐짐
안 될 때: 새로고침 후 최신 Chrome/Edge에서 다시 열고, 배포된 index.html/style.css/script.js 경로를 확인

## AI와 내 판단 3줄 — 제출 전 본인 말투로 확인/수정
AI에게 맡긴 일: 페이지 구조 초안, 반응형 CSS, 접근성 및 상호작용 코드의 초안을 만드는 데 도움을 받았습니다.
내가 판단한 일: 공개할 정보의 범위와 실제 경험 중 무엇을 소개할지 직접 정하고 최종 내용을 검토했습니다.
AI 제안을 따르지 않은 일: 과제와 관계없는 개인정보나 과장된 경력은 넣지 않고, 실제 공개 가능한 내용만 사용했습니다.

## 제출 전 직접 할 일
1. 모든 문장이 실제 본인 경험과 일치하는지 확인하고 다르면 수정합니다.
2. 공개 배포 후 1366×768 / 1920×1080에서 첫 화면과 가로 넘침을 확인합니다.
3. 모든 버튼을 마우스와 Tab/Enter/Space로 검사합니다.
4. DevTools Console에 오류가 0개인지 확인합니다.
5. 공개 결과물 URL과 소스 저장소 URL을 제출창에 입력합니다.
