## 게임 요약

RAID//ZERO는 28초 동안 보스 패턴을 피하는 브라우저 미니게임입니다. 로그인·회원가입·외부 API 없이 정적 HTML/CSS/JavaScript만으로 실행됩니다.

- 성공: 28초 생존
- 실패: HP 5가 모두 소진
- 핵심 조작 3개: 이동(WASD/방향키), 대시(Space), 일시정지(P)
- 3단계 페이즈: 0~8초 / 8~18초 / 18~28초
- 현재 상태 표시: 남은 시간, HP, 점수, 페이즈, 처리 입력 수
- 저장: localStorage에 실험 기록·최고점수·효과 설정만 보존
- 현재 판의 HP·시간·위치·점수는 새 게임 시 항상 초기화

## 난이도 비교 실험

비교 시 단 하나의 값만 변경합니다.

- A 기준: 패턴 생성 간격 720ms
- B 조정: 패턴 생성 간격 620ms
- 고정: 플레이어 이동량, HP, 대시 거리/무적시간, 라운드 28초, 기본 패턴 로직

게임 오른쪽의 `20회 난이도 실험 기록`에 매 판의 설정(A/B), 성공·실패, 생존 시간, 점수가 자동 저장됩니다. **제출 전 A 10회 + B 10회를 실제로 플레이해 기록을 채웁니다.** 실패해도 1회 기록으로 인정되므로 반복 실패 원인도 비교 근거가 됩니다.

## 최종 확인 질문 답안

### ① 어디로 가나요?

위 `결과물 URL`로 이동합니다. 별도 로그인 없이 바로 게임 화면이 열립니다.

### ② 무엇을 하나요? — 3단계

1. `게임 시작`을 누릅니다.
2. WASD/방향키로 이동하고 필요하면 Space로 대시해 붉은 패턴을 피합니다.
3. 28초 생존하거나 HP가 0이 될 때까지 플레이한 뒤 결과 화면과 자동 저장된 기록을 확인합니다.

### ③ 무엇이 보이면 통과인가요?

게임 화면에 남은 시간·HP·점수·페이즈가 계속 보이고, 입력에 따라 플레이어가 한 번씩 움직이며, 한 판이 28초 안에 `MISSION CLEAR` 또는 `MISSION FAILED`로 종료되면 통과입니다. 종료 뒤 `다시 시작`하면 현재 판의 HP·시간·점수·위치가 초기화되고 실험 기록은 남아 있어야 합니다.

### ④ 안 될 때 무엇이 보이나요?

게임 화면이 열리지 않거나, 조작해도 플레이어가 움직이지 않거나, 타이머가 멈추지 않은 채 일시정지가 되거나, 종료 후 다시 시작했는데 이전 판 HP·시간·점수가 남아 있으면 실패입니다. 손상된 저장값 때문에 흰 화면/중단이 발생해도 실패입니다.

## AI 사용 구분

### ① AI에게 맡긴 일

- HTML/CSS/JavaScript 구조 초안과 게임 루프 구현
- 1366×768 / 1920×1080 반응형 레이아웃 설계
- 키 자동반복 방지, 일시정지, 포커스 이탈 처리
- localStorage 기본값·손상 복구 로직
- 효과 ON/OFF, 난이도 A/B 기록 기능
- 제출 조건 C01~C31 대조와 코드 문법 점검

### ② 학생이 직접 판단한 일

- 패턴 회피 장르를 선택
- 한 판을 28초로 구성
- 핵심 조작을 이동·대시·일시정지 3개로 제한
- 난이도 비교 변수는 `패턴 생성 간격` 하나만 쓰기로 결정
- 개인정보·계정·외부 API가 필요 없는 독립 실행형 게임으로 제출하기로 결정
- 실제 A 10회/B 10회 플레이 결과를 보고 최종 난이도 선택 및 이유를 작성

### ③ AI 제안을 따르지 않은 일

이번 최종 범위에서는 별도의 생성형 AI/API 기능을 넣지 않았습니다. 미니게임 자체에 필요하지 않고, 공개 브라우저 코드에 API 비밀정보를 둘 위험과 외부 의존성이 생기기 때문입니다. 최종 제출물은 외부 AI 호출 없이 실행되도록 결정했습니다.

## 제출 직전 남은 실제 확인

코드·문법 및 핵심 동작은 구현했지만, 채점 문구가 요구하는 **실제 PC 10분 연속 실행**과 **A 10회/B 10회 실제 플레이 기록**은 학생 PC에서 수행해 최종 확인해야 합니다. 이 두 항목은 수행하지 않고 했다고 적지 않습니다.
