# T02 조건 대응 및 증거 — RAID//ZERO

## 카드 1 — 30초 핵심 규칙

- **T02-C01** 결과/소스 주소를 공개 GitHub Pages / Public GitHub 저장소로 제출한다. 최종 제출 전 InPrivate 창에서 결과·소스 두 주소를 직접 확인한다.
- **T02-C03** 핵심 규칙 3개를 게임 오른쪽 패널에 항상 표시한다.
- **T02-C04** WASD/방향키, Space, P, R 조작을 항상 표시한다.
- **T02-C05** 남은 시간, Phase, HP, Score, Combo, Dash, State를 항상 표시한다.
- **T02-C06** 핵심 입력 Space는 `keydown` 1회당 `coreDashAction()` 1회만 호출한다. `event.repeat`은 무시한다. 디버그 카운터 `coreInputEvents`와 `coreActions`로 확인 가능하다. 쿨다운 중 입력도 1회 처리 후 BLOCKED로 종료하며 중복 실행하지 않는다.
- **T02-C07** 한 판 최대 시간이 28초라 시작 후 성공/실패까지 30초 안에 끝난다.
- **T02-C08/C09** 성공/실패 뒤 재시작 시 `createFreshState()`로 시간 28, HP 5, Score 0, Combo 0, Phase 1, 패턴 0개, 플레이어 시작 위치로 초기화한다.

## 카드 2 — PC 경계 검사

- **T02-C10/C11** CSS는 `minmax(0,1fr)`, `overflow-x:hidden`, 반응형 breakpoints를 사용한다. 1366×768 및 1920×1080에서 게임 시작 영역과 핵심 UI가 잘리지 않고 가로 넘침이 없어야 한다.
- **T02-C12** 1초 안에 같은 Space 입력 이벤트 10회를 보낼 때 `event.repeat=false`인 10개 이벤트 각각이 `coreDashAction()` 1회로 연결된다. `window.__raidZeroDebug.getCounters()`로 이벤트/액션 카운트를 비교한다.
- **T02-C13** 창 크기 변경 이벤트는 게임 상태를 재생성하지 않고 UI만 동기화한다.
- **T02-C14** 포커스를 잃으면 현재 판을 유지한 채 자동 일시정지하고, 돌아와도 판 상태를 새로 만들지 않는다. 사용자가 P로 재개한다.
- **T02-C15** `mode==='paused'`에서는 update가 즉시 반환되어 시간/HP/점수/패턴이 변하지 않는다.
- **T02-C16/C17** 최종 공개 URL에서 실제 PC 10분 연속 실행 후 조작 가능 여부와 DevTools Console red error 0건을 최종 확인한다. 이 두 항목은 실제 시간 검사가 필요하므로 제출 직전 수동 확인 결과를 아래에 기록한다.

- 10분 뒤 조작 가능: [ ] PASS

## 카드 3 — 10회 전후 난이도 선택

난이도 비교에서는 **패턴 기본 생성 간격 한 값만** 변경했다. 나머지 HP, 이동속도, 대시 거리, 대시 쿨다운, 한 판 시간은 동일하다.

- 변경 전: `ATTACK_INTERVAL_MS = 920`
- 변경 후/최종: `ATTACK_INTERVAL_MS = 740`
- 기록 방식: Chromium에서 동일한 자동 회피 QA 로직과 동일한 10개 반응 수준을 사용해 전/후를 각각 10판 실행했다. 게임 로직의 시간을 가속해 QA했으며, 한 판의 판정 기준 자체는 28초/HP 5로 동일하다.

## 카드 4 — 저장과 손상 복구

- **T02-C22** 새 판 시작 시 현재 판 상태는 항상 Fresh State로 초기화한다.
- **T02-C23** 보존한다고 선언한 `클리어 수/최고 점수/최장 생존`만 localStorage에 남긴다.
- **T02-C24** 저장 키가 없으면 `{wins:0,bestScore:0,bestTime:0}` 기본값으로 시작한다.
- **T02-C25** JSON 파싱 실패, 문자열/음수/NaN/범위 밖 값은 `sanitizeRecord()`가 기본값으로 복구하며 게임은 중단되지 않는다.

검사 예시(DevTools Console):

```js
__raidZeroDebug.clearSave();
location.reload();
// 기록 0/0/0으로 정상 시작

localStorage.setItem('raidzero:v1', '{broken json');
location.reload();
// 오류로 중단되지 않고 기록 0/0/0으로 정상 시작
```

## 카드 5 — 효과와 제출 안전

- **T02-C26** 파티클/흔들림 효과는 대시, 피격, 클리어/실패 결과 이벤트에서만 실행한다.
- **T02-C27** `파티클/흔들림 줄이기` 버튼을 켜면 새 효과 생성을 멈추고 기존 파티클 배열과 화면 흔들림 값을 즉시 0으로 만든다.
- **T02-C28** 공개 화면/제출 문구에 개인 연락처, 정확한 위치 등 공개하지 않기로 한 개인정보를 넣지 않는다.
- **T02-C29** 공개 화면/배포 파일/제출 문구에 비밀번호, 토큰, API key, 모델 key 등 비밀값을 넣지 않는다.
- **T02-C30** README에 `어디로/3단계 이내 행동/통과 화면/실패 화면` 4가지를 분리해 적는다.
- **T02-C31** README에 `AI에게 맡긴 일/내가 직접 판단한 일/AI 제안을 따르지 않은 일` 3가지를 분리해 적는다.
