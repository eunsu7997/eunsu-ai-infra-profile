# T02 — Server Shield 증거 기록

## 게임 개요
- 장르: 클릭/키보드 20초 생존 미니게임
- 규칙: CPU 부하가 100%에 닿기 전에 `SPACE` 또는 `COOL` 입력으로 부하를 낮추며 20초를 버티면 성공한다.
- 현재 판 값: 상태, 남은 시간, CPU 부하, 냉각 입력 수
- 보존 값: 성공 횟수, 최장 생존 시간
- 결과 효과: 성공/실패 때 파티클 버스트. `효과 줄이기`를 켜면 즉시 제거되고 이후 생성되지 않는다.

## 조건 대응표
- **T02-C01** 결과/소스 URL은 공개 GitHub Pages/GitHub 경로를 사용한다. 최종 제출 전 InPrivate에서 수동 확인한다.
- **T02-C03** 오른쪽 규칙 패널에 게임 규칙을 공개한다.
- **T02-C04** SPACE, P, R 핵심 조작을 공개 화면에 표시한다.
- **T02-C05** 상태/남은 시간/냉각 입력/CPU 부하를 공개 화면에 표시한다.
- **T02-C06** SPACE 또는 COOL 1회당 `actions +1`, `load -9`가 정확히 한 번 반영된다.
- **T02-C07** 한 판은 최대 20초 안에 성공 또는 실패한다.
- **T02-C08/C09** 성공/실패 뒤 다시 시작하면 현재 판의 상태·시간·부하·입력 수가 초기화된다.
- **T02-C10/C11** 1366×768 및 1920×1080에서 시작 영역 잘림과 가로 넘침이 없도록 반응형으로 구성한다.
- **T02-C12** 단일 keydown 리스너에서 SPACE 이벤트 한 건당 `coolOnce()`를 한 번만 호출한다. 자동검사에서 1초 이내 10건 → 입력 수 +10 확인.
- **T02-C13** resize 때 게임 상태를 재생성하지 않아 상태와 조작이 유지된다.
- **T02-C14** 포커스 이탈 시 진행 중이면 자동 일시정지하고, 복귀 뒤 P로 같은 상태에서 재개한다.
- **T02-C15** 일시정지 중 requestAnimationFrame 루프를 중단해 시간/부하가 진행되지 않으며 재개 뒤 이어진다.
- **T02-C16/C17** 자동 가속 반복 검증에서 10분 상당 반복 실행 뒤 입력 가능/콘솔 오류 0을 확인했다. 최종 제출 전 실제 브라우저 10분 수동 실행도 한 번 확인한다.
- **T02-C18~C21** 아래 20회 난이도 비교 기록과 최종 선택 근거를 사용한다.
- **T02-C22** 새 게임에서 현재 판 값이 초기화된다.
- **T02-C23** `wins`, `bestSurvivalMs`만 localStorage에 보존한다.
- **T02-C24/C25** 저장 키 없음/빈 값/손상 JSON/타입 손상은 안전한 기본값 `{wins:0,bestSurvivalMs:0}`으로 복구한다.
- **T02-C26** 파티클은 선언한 성공/실패 결과 이벤트에서만 발생한다.
- **T02-C27** 효과 줄이기 ON 시 현재 파티클을 즉시 삭제하고 이후 파티클도 만들지 않는다.
- **T02-C28/C29** 개인정보와 비밀값(비밀번호·토큰·API 키 등)을 페이지/소스/제출문에 넣지 않는다.
- **T02-C30/C31** 제출용 짧은 확인 방법 4가지와 AI/내 판단 3가지를 아래에 구분한다.

## 20회 난이도 비교 기록

### 최종 난이도 선택 이유
`6.4%/초`는 동일 전략 10회가 모두 성공해 후반 긴장감이 낮았다. `7.0%/초`는 **18.05~20.00초 범위, 8/10 성공**으로 대부분 완주할 수 있으면서 입력 간격이 길어질 때 마지막 스파이크에서 실패하는 원인이 반복 확인됐다. 따라서 성공 가능성을 유지하면서 조작 의미가 더 분명한 **7.0%/초**를 최종값으로 선택했다.

## 저장값 검사
- 정상 값 `{"wins":3,"bestSurvivalMs":12345}` → 두 값을 읽어 화면 기록에 반영.
- 키 없음/빈 값 → 기본값 `0 / 0.0s`로 시작.
- 손상 JSON `{broken` → 파싱 예외를 잡고 기본값으로 시작, 게임 중단 없음.
- 타입 손상 `{"wins":"x","bestSurvivalMs":null}` → 필드별 검증 후 기본값 사용.

## 제출용 짧은 확인 방법
**어디로 가나요:** https://eunsu7997.github.io/eunsu-ai-infra-profile/t02-mini-game/

**무엇을 하나요(3단계 이내):** 1) 게임 시작 2) SPACE 또는 COOL로 20초 동안 부하를 낮춤 3) 결과 화면에서 다시 시작하고 효과 줄이기를 켜 봅니다.

**무엇이 보이면 통과:** 상태·남은 시간·CPU 부하가 실시간으로 변하고 20초 안에 성공/실패 결과가 나온 뒤, 다시 시작하면 현재 판 값이 초기화됩니다. 효과 줄이기를 켜면 결과 파티클이 즉시 사라지고 이후 생성되지 않습니다.

**안 될 때 무엇이 보이나요:** 입력 1회에 상태가 여러 번 변하거나, 일시정지 중 시간이 줄거나, 재시작 후 이전 판 값이 남거나, 가로 스크롤·멈춤·브라우저 콘솔 빨간 오류가 보입니다.

## AI와 내 판단
**AI에게 맡긴 일:** 과제 조건을 기준으로 게임 구조, 반응형 UI, 상태 머신, 저장값 검증, 효과 줄이기, 자동 검사와 코드 초안을 작성하고 조건 누락을 점검하게 했습니다.

**내가 직접 판단한 일:** 서버 과부하 방어라는 주제, 공개할 정보, 핵심 조작, 최종 난이도와 실제 플레이 감각이 과제 목적에 맞는지 직접 판단했습니다.

**AI 제안을 따르지 않은 일:** 과제에 필요 없는 로그인·온라인 랭킹·외부 API는 복잡도와 비밀값 위험을 늘리므로 넣지 않고, 브라우저에서 바로 실행되는 단일 플레이 게임으로 범위를 제한했습니다.
