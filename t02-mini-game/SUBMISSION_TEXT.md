## 짧은 확인법

**어디로 가나요**  
결과 주소로 이동합니다.

**무엇을 하나요 — 3단계 이내**  
1. `훈련 시작`을 누릅니다.  
2. WASD/방향키로 장판을 피하고 필요할 때 Space로 대시합니다. 대시 직후 0.5초 무적이며, 노란 실드 코어를 먹으면 1.5초 무적입니다.  
3. 성공/실패 화면에서 R 또는 `다시 시작`을 눌러 새 판을 확인합니다.

**무엇이 보이면 통과인가요**  
규칙·조작·남은 시간·Phase·HP·Score·Combo·Dash·Shield·State가 계속 표시되고, 한 판은 28초 안에 성공/실패 결과가 납니다. 결과 뒤 재시작하면 시간 28.0, HP 5, Score 0, Combo 0, Phase 1과 시작 상태로 초기화됩니다. P로 일시정지하면 시간이 멈추고 재개 후 같은 판에서 이어집니다.

**안 될 때 무엇이 보이나요**  
핵심 입력 1회가 여러 번 처리되거나, 재시작 뒤 이전 판 상태가 남거나, 일시정지 중 시간이 진행되거나, 창 크기/포커스 변경 뒤 조작이 끊기거나, 1366×768·1920×1080에서 화면이 잘리거나 가로 스크롤이 생기거나, Console 빨간 오류가 발생하면 실패입니다.

## AI와 내 판단

**AI에게 맡긴 일**  
과제 조건을 기능 요구사항으로 정리하고, 게임 코드·반응형 레이아웃·저장값 복구·효과 줄이기·디버그 확인 기능·조건별 QA 문서를 구현하고 누락 조건을 점검했습니다.

**내가 직접 판단한 일**  
단순 게이지형 게임 대신 직접 움직여 보스 패턴을 피하는 RAID//ZERO 콘셉트를 선택했습니다. 과제의 30초 제한을 맞추기 위해 한 판을 28초로 정했고, HP 5·3단계 페이즈·대시 중심 조작을 유지했습니다. 0.65초 패턴은 직접 플레이했을 때 너무 빡세다고 판단했습니다. 대시 후 0.5초 무적과 1.5초 실드 코어 아이템을 추가하고, 같은 조건의 10회 비교 결과를 확인한 뒤 기본 패턴 간격을 0.75초로 최종 완화했습니다. Phase 3 추적 도넛은 너무 크게 느껴져 최종적으로 크기를 줄였습니다.

**AI 제안을 따르지 않은 일**  
초기 제안이었던 CPU 게이지를 버튼으로 낮추는 Server Shield 방식은 게임성이 부족하다고 판단해 사용하지 않았고, 직접 움직이는 레이드 회피 게임으로 변경했습니다. 단순한 빨간 점 형태 보스도 사용하지 않고 페이즈에 따라 색과 맥동이 변하는 보스 코어 형태로 수정했습니다.
