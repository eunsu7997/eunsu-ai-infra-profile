# RAID//ZERO — ALEPH T02 최종 제출본

브라우저에서 실행되는 **28초 보스 패턴 회피 미니게임**입니다.

- 결과 주소: https://eunsu7997.github.io/eunsu-ai-infra-profile/t02-mini-game/
- 소스 주소: https://github.com/eunsu7997/eunsu-ai-infra-profile/tree/main/t02-mini-game
- 핵심 조작: WASD/방향키 이동, Space 대시(직후 0.5초 무적), P 일시정지, R 결과 화면에서 재시작
- 실드 코어: 한 판에 1~2회 등장하며 획득 시 1.5초 무적
- 성공: 28초 생존
- 실패: HP 0
- 최종 기본 패턴 간격: 0.75초 (`INT = 750`)
- 페이즈: 1(기본 장판) → 2(레이저/도넛) → 3(복합 패턴/광폭화)

## T02 제출용 짧은 확인법

### 1) 어디로 가나요
결과 주소로 이동합니다.

### 2) 무엇을 하나요 — 3단계 이내
1. **훈련 시작**을 누릅니다.
2. WASD/방향키로 장판을 피하고 필요할 때 **Space**로 대시합니다. 대시 직후 0.5초 무적이며, 노란 **실드 코어**를 먹으면 1.5초 무적입니다.
3. 성공/실패 결과 화면에서 **R** 또는 **다시 시작**을 눌러 새 판을 확인합니다.

### 3) 무엇이 보이면 통과인가요
- 공개 게임 화면에서 규칙, 조작, 남은 시간, Phase, HP, Score, Combo, Dash, Shield, State가 계속 보입니다.
- 한 판은 최대 28초 안에 성공 또는 실패 결과가 나옵니다.
- 결과 뒤 재시작하면 시간 28.0, HP 5, Score 0, Combo 0, Phase 1, 시작 위치/패턴 상태로 초기화됩니다.
- 일시정지 중에는 판 시간이 진행되지 않고, 재개하면 같은 판에서 이어집니다.

### 4) 안 될 때 무엇이 보이나요
- 핵심 입력 1회가 여러 번 처리됨
- 재시작 뒤 이전 판의 HP/점수/패턴이 남음
- 일시정지 중 시간/패턴이 진행됨
- 창 크기 변경 또는 포커스 복귀 뒤 조작이 끊김
- 1366×768 / 1920×1080에서 시작 영역이 잘리거나 가로 스크롤이 생김
- DevTools Console에 빨간 오류가 발생함

## AI와 내 판단

### AI에게 맡긴 일
과제 조건을 기능 요구사항으로 정리하고, 게임 코드·반응형 레이아웃·저장값 복구·효과 줄이기·디버그 확인 기능·조건별 QA 문서 초안을 구현하고 누락 조건을 점검했습니다.

### 내가 직접 판단한 일
처음의 단순 게이지형 게임 대신 **직접 움직여 보스 패턴을 피하는 RAID//ZERO** 콘셉트를 선택했습니다. 한 판 길이는 과제의 30초 제한을 맞추기 위해 28초로 정했고, HP 5, 3단계 페이즈, 대시 중심 조작을 유지했습니다. 0.65초 버전은 직접 플레이했을 때 너무 빡세다고 판단했고, 실드/대시 무적을 포함한 동일 조건 10회 비교 후 기본 패턴 간격을 **0.75초**로 완화했으며, 이후 직접 플레이 피드백으로 **대시 후 0.5초 무적**과 **1.5초 실드 코어 아이템**을 추가했습니다. Phase 3의 추적 도넛 패턴은 너무 크게 느껴져 최종적으로 크기를 줄였습니다.

### AI 제안을 따르지 않은 일
초기 제안이었던 CPU 게이지를 버튼으로 낮추는 **Server Shield** 방식은 게임성이 부족하다고 판단해 사용하지 않았습니다. 이후에도 단순한 빨간 점 형태의 보스 표현 대신 보스 코어/회전 링/페이즈 변화가 보이는 형태로 수정했습니다.

세부 조건 대응과 검증 결과는 `T02_EVIDENCE.md`와 `T02_FINAL_CHECKLIST.md`에 정리합니다.
